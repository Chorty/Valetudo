# 2026-11-05 capture port and dependency update

Deployed as `sec1105` by the owner on 2026-11-05, finishing at 18:03:16 EST, and verified on the robot. Only the Home Assistant comparison is still open. The robot previously ran `db6adc04` (`miio1103`).

## What changed

- **Capture port** ([native PR #24](https://github.com/Chorty/vacuumstreamer/pull/24), merge `9b8386e99b513dc4d32e89394f30a8a3e4a1050b`): the shim binds its capture port to loopback. go2rtc already reads it at `tcp://127.0.0.1:6969`, and `vs_tcp_port_state` matches on the port alone, so the wake script and supervisor need no change.
- **Installing the shim** (same PR): `deploy_native.sh` can't install `vacuumstreamer.so`, because it exports tracked files and `*.so` is gitignored. The new `tools/install_shim.sh` installs a pinned build after the native stage, and the reboot gate's rollback now includes the shim.
- **Dependencies** ([PR #56](https://github.com/Chorty/Valetudo/pull/56), merge `566357b75f42dc282e21be827a4968a732fc0f51`): `compression` 1.8.2 and `body-parser` 2.4.0.

Plugin `5ccddae` is unchanged. Apart from docs, the dependency update is the only difference from the deployed Valetudo commit. The native runtime scripts are also unchanged.

## Dependencies

`backend/package.json` pins `compression`, so that takes one line. `express` 5.2.1 asks for `body-parser` `^2.2.1`, so `body-parser` needs only a lockfile change and no override.

The lockfile also moves what those two require: `content-type` 2.1.0 (nested under `body-parser` and `type-is`), `destroy` 1.2.0 (new), `iconv-lite` 0.7.3, `qs` 6.16.1, `side-channel` 1.1.1, `side-channel-list` 1.0.1 and `type-is` 2.1.0. Each is the lowest version its dependent accepts. No other package moved. `mcp-server/` has its own lockfile and is unchanged.

`npm audit --omit=dev` went from 23 to 20 entries: `body-parser`, `compression` and `qs` are gone, and nothing new appeared.

**At the next upstream sync:** once upstream's lockfile has `body-parser` 2.4.0 or later and `compression` 1.8.2 or later, take upstream's `backend/package.json` line and lockfile entries, and this fork difference goes away.

## Shim build

The `Dockerfile` image (Debian 13.7, clang 19.1.7, local image `valetudo-native-sec1105:local`) rebuilt the unchanged source byte for byte to the deployed `8b826b44…`. That identifies the toolchain, which had not been recorded, and means the comparison below shows only this change.

| Check | Result |
|---|---|
| New shim | `2c541c63071f81ea85fdc9b1f2d4a198bbc26d0449e79ad355a8515ac2f6646e`, 154,280 bytes, matches the pin in `install_shim.sh` |
| `NEEDED` | `libc.so.6` only, unchanged |
| Required symbol versions | `GLIBC_2.17` only, unchanged |
| `serverThread` | `mov w0, wzr` becomes `mov w0, #1; movk w0, #0x7f00, lsl #16`; all 55 internal branches land on the corresponding instruction |
| The other 434 functions | Identical once references are resolved to section and offset |
| `.rodata`, `.data`, `.got`, `.plt`, `.dynstr`, `.rela.plt` | Byte-identical |

This isn't a one-word binary change. The constant takes one more instruction, so `.text` grows by 4 bytes. Later code, `.rodata` and `.eh_frame` move by 4 or 8 bytes, and 401 of 433 dynamic symbols change value by 4. The file size is unchanged.

A local container run called the shim's init entry point in each build. The old one listened on `00000000:1B39`. The new one listened on `0100007F:1B39`, accepted a connection on `lo` and refused one on `eth0`.

**The reboot gate doesn't test the new shim.** In `on_demand` mode the gate doesn't wake the camera. `install_shim.sh` checks that the robot's loader accepts the file, but only a camera wake after the gate shows that it serves video. The loader check looks at output as well as status, because `ld.so` exits 0 for a preload it can't use; that was confirmed on the robot with the installed library and two invalid paths.

## Deployment

The owner ran `DEPLOY_COMMANDS.sh` with the robot docked and idle:

| Stage | Result (EST) |
|---|---|
| Check | Seal, artifact, shim and `tools/` verified, 17:53 |
| Binary | 60 s gate passed, 17:56:39 |
| Native | Files installed from `9b8386e`, 17:57:14 |
| Shim | **Stopped:** `tools/install_shim.sh: Permission denied`. Run with `bash` instead, finished 18:01:16 |
| Reboot | Back at 18:01:48, 12/12 at 18:03:13, finished 18:03:16 |

**The stop:** `install_shim.sh` was committed without its executable bit. The native tests ran it with `bash` and the deploy script's own checks used stand-in tools, so neither saw it. No file had changed for that stage, so the robot was left safe, on the new binary and old shim. `chmod` wasn't an option during the deploy, because the script's check treats a mode change as a change to `tools/`. [Native PR #25](https://github.com/Chorty/vacuumstreamer/pull/25) sets the bit, on `install_caddy.sh` too, and adds a test.
