# 2026-11-05 LAN firewall, key-only SSH and go2rtc API: built, not deployed

The package for deploy `lan1105` is built and sealed. **The owner has not run it, so the robot still runs `sec1105`.** This page becomes the deployment record once it's deployed and verified.

The Valetudo binary doesn't change (`566357b7`, `f1705a24…`), so this is a native-only deploy.

## What changes

All from [native PR #26](https://github.com/Chorty/vacuumstreamer/pull/26), merge `4f9c9454362f97b3172f2710db05257d488a23af`:

- **go2rtc API:** binds to `127.0.0.1:1984`. The robot's scripts and the plugin's camera relay already use loopback. RTSP stays on the LAN.
- **`LAN_FIREWALL` switch:** `lan_firewall.sh` drops inbound IPv4 on `wlan0` for TCP 80 and UDP 54321, and turns IPv6 off on `wlan0`, because this kernel can't filter IPv6. It checks every 30 s, because rules don't survive a reboot and the firmware's `wifi_start.sh` flushes them when it changes networks. It leaves the rules alone while the firmware runs its own firewall, which sets INPUT to DROP on a hidden network. Port 80 is only blocked with `HTTPS_PROXY=on`.
- **Key-only SSH:** `tools/ssh_keys_only.sh` sets the firmware's own switch, `/mnt/misc/ssh_disable_passwords`, which `/etc/rc.d/dropbear.sh` reads at boot. There's no easy way back in if key login fails after the reboot, so it first logs in through a temporary key-only server on loopback.
- **Caddy allowlist:** adds the owner's Mac, `192.168.1.113`, which has a fixed IP in UniFi.
- **`deploy_binary.sh`:** the artifact's own path and hash must both be in the package's seal.

## What stops working

- **Home Assistant's still image URL** uses port 1984. The owner clears it before deploying. The stream source stays on RTSP. HA's thumbnail without a still URL hasn't been checked.
- **Plain HTTP to the robot from other devices.** HA, the iPhone and the Mac use HTTPS through Caddy, and any other device needs an SSH tunnel. The "Visit" link on the HA device, `http://valetudo-<id>.local`, stops working. A 10-minute sample of port 80 saw only robot localhost and the owner's Reolink doorbell, which doesn't need Valetudo.
- **go2rtc's web UI, API-based HLS and WebRTC signalling** need a tunnel. The plugin's `urls` route still lists those URLs, and fixing that needs a Valetudo build, so it waits for the next one. Nothing here is known to use them.

RTSP and the go2rtc password stay on the LAN, so a captured password still gives video.

## Validation

- **Native tests:** `sh test/run_tests.sh dash` and `sh`, 374 passed. Breaking each of six new checks in a scratch copy made the tests fail. iptables and dropbear are stubbed there, so **none of this has run on the robot**.
- **Read-only on the robot:** iptables 1.8.7 supports `-C` and `-S`, the kernel has no `REJECT` target, so the rules use `DROP`, and dropbear 2020.81 has `-s` and `-P`. A snapshot showed no IPv6 connections, and MQTT and DNS use IPv4 addresses.
- **Deploy script:** a copy passed 42 checks against a stand-in robot and a temporary checkout: stage order, stopping on a failed stage, a different binary, a tampered package, changed tools, a tool without its executable bit, and the rollback. The rollback hasn't run on the robot.
- **Pre-deploy IPv6 test:** the owner's phone, on cellular with working IPv6, timed out on ports 80 and 1984 of the robot's global address. That's two ports from one network.

## Deploying

Owner-run, with the robot docked and idle, after clearing HA's still image URL:

```bash
bash ~/Documents/ValetudoBackups/valetudo_lan1105_20261105/DEPLOY_COMMANDS.sh
```

It verifies the seal, `tools/` and each tool's executable bit, then keeps the binary, installs the native files, sets the switches and runs the reboot gate. It also takes a stage name to run one at a time. Keep native `tools/` at `4f9c945` until then, because the check stops on any difference.

## Rollback

`DEPLOY_COMMANDS.sh rollback` restores every preserved `.predeploy_lan1105` file, removes the SSH switch and reboots. The reboot clears the firewall rules and brings IPv6 back. The reboot gate's automatic rollback restores the files but not the SSH switch.
